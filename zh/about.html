关于本页

这个网站是一趟真实行程的计划：四个朋友，2026 年 10 月 25 日至 11 月 1 日，布达佩斯、维也纳和奥地利萨尔茨卡默古特的湖区。计划由 AI agent 写成，行程中随时更新。这种做法现在做成了一个开源项目：tripwright。

你看到的是什么

行程结束时的计划。网站最后生成于 2026-10-31 14:03（维也纳时间），之后不再更新。时刻、票价和开放时间只按当时的日期核过；拿来排自己的行程前，请再核一遍。

从首页看起：首页有路线、每天一行、怎样看每天的页面。每天的页面再给出定死的时刻、按顺序去的地方和地图链接、每人一列的时间轴，以及其他方案。

计划怎样做出来

  • 说。排行程的那位旅行者用聊天消息把大家想要什么告诉 AI agent，很多是语音转的文字。行前和路上，每条消息都可能加一个愿望、一项预订或一处纠正。
  • 记。agent 把这些都记在一个私有的行程仓里：谁想要什么，候选地点和照片、价格，车票与预约，以及每条决定、它出自哪句话、为什么这样定。决定页列了其中 68 条。
  • 查。agent 用 Transitous 的开放时刻表数据查火车和巴士，用 Open-Meteo 查天气预报。查不了的地方，页面上写明“没核”“没查到”。
  • 改。天气、晚点的巴士或新的想法打乱当天安排时，agent 重新排，写下原因，再重新生成这个网站。大家在手机上看每天的页面。

生成本站、查交通用的小程序在工具代码（MIT 许可）。

公开前去掉了什么

  • 不写人名：排行程的人写成“我”“本人”，其他人写成“队友”“同行人”。从社交媒体引用的人写成“一位小红书博主”。
  • 住的地方只写类型和城镇或城区（维也纳写到邮编区）；住处名、门牌、住处旁的站、进出住处的时刻和步行时长都不写。公共地点之间的时刻和车次照写，所以熟悉线路的人仍能大致估出远近。
  • 不写航班号、订单号、个人电话和邮箱。航空公司、日期和时刻保留。
  • 图片作者署名按授权要求保留（见图片来源）。

tripwright 是什么

tripwright 是给 AI 助手用的开源旅行规划服务。Claude、ChatGPT、Codex 这类助手通过 MCP（Model Context Protocol，模型上下文协议，AI 应用调用外部工具的标准方式）连上它；各家应用允许做的事不一样，README 写了各家的限制。回答由你的助手写，tripwright 给它该记住的东西和要核的事实。

  • 把你说过的带回来。每一问，它都取出适用的偏好、同行人、决定和想去的地方，让助手按你以前说的排，不只看最近一句话。
  • 分两段回答。先按存的计划给下一步，没核的时刻标明待核；查完再给完整安排，先说和第一段哪里不同。
  • 交通写清数据覆盖到哪。每一程写出车次、站点、换乘和查询的时间窗。一次没查到，报“查不到”，不说“没车”。拿不到的实时信息，写明去哪个 App、搜什么。
  • 每次改动都有记录。接受的计划改动记下改了什么、谁改的、为什么。你说了“必须”的地方与时间、已经买好的票受保护；其他选择可以带理由调整。
  • 数据在你手里。行程存在你自己的 Git 仓或本机数据库里，能看每天的安排和历史，也能导出。

限制。没有公共服务：每个人用 Docker 或在 Railway 上自己部署一份。交通数据主要是时刻表，不是实时的；晚点、站台、余位不作保证。服务本身不带模型，回答好不好取决于你的助手；回答质量还在评测中。

本页和 tripwright 的关系

这趟行程用的是这种做法的第一版：AI agent 在私有行程仓里工作，配合工具代码里的小工具。tripwright 把这种做法重做成一个服务，任何支持 MCP 的助手都能用。

这趟行程也作为例子放在 tripwright 仓里，人名换成了代号：examples/trip-2026-10-bud-wien。那里能看到 tripwright 在行程仓里维护的页面：每天的安排、偏好与记忆、计划为什么改。

看代码、自己用

  • 代码和文档：github.com/zlxdengtianhei/tripwright（MIT 许可）。
  • 项目首页：zlxdengtianhei.github.io/tripwright。
  • 自己部署一份：把 deploy/SETUP.md 交给你的编程 agent（Claude Code、Codex 等）照着做。你只需注册 Railway 或装好 Docker，再在 AI 应用里加上连接器。
  • 想先在自己电脑上用虚构的行程试一下（要 Python 3.11 以上和 uv）：
git clone https://github.com/zlxdengtianhei/tripwright
cd tripwright
uv sync --extra dev
uv run tripwright demo

页面上的用词

“我”“本人”“用户”
和 AI agent 一起排行程的那位旅行者。页面是写给路上的大家看的，所以也常说“你”。
“队友”“同行人”
另外三位旅行者。“全组”指四个人。
硬节点、关键时刻
不能挪的时刻：火车、巴士、限时门票、预约。
推荐的一套（时间轴第一套）
大家默认照着走的方案。这天的其他方案放在旁边。
D-44、Q-07
决定（D）和待定问题（Q）的编号。决定页逐条说明。
“已过”“做完”
行程中给旅行者看的标记。现在所有时刻都显示“已过”。“做完”只记在你点它的那台设备上。
